데이터 적재 흐름

  1. 1Airflow가 지시한다

    정해진 시각에 어떤 작업을 어떤 순서로 돌릴지 정하고, 실제 계산은 Spark · Tez에 맡긴다. 데이터는 Airflow를 지나가지 않는다.

  2. 2Iceberg 갈래 — Spark

    Spark가 원천 데이터를 읽어 Iceberg 테이블에 새 데이터만 덧붙인다(append).

  3. 3Hive 갈래 — Tez

    Tez가 Hive SQL을 실행해 _raw에 쌓고, 배치 주기마다 ORC로 바꿔 _orc의 파일과 교체한다.

  4. 4갈래가 둘인 이유

    Hive에서 Iceberg로 옮기는 중이다. 최근 옮긴 테이블은 두 곳에 함께 쌓는다.

상자를 누르면 역할 · 비유가 열린다 · Spark · Tez는 YARN이 나눠 준 CPU · 메모리로 돌고, 테이블 파일은 모두 HDFS에 있다

구성요소별 역할

Airflow

지시
언제, 무엇을, 어떤 순서로 실행할지 정한다
작업 일정표를 든 작업반장
정해진 순서와 조건대로만 움직이고, 데이터는 직접 만지지 않는다

YARN

자원
클러스터의 CPU · 메모리를 작업에 나눠 준다
공용 작업장의 자리 배정 담당
나눠 주는 것은 자리가 아니라 CPU · 메모리 묶음(container)이다

Spark

계산
큰 계산을 쪼개 여러 서버에서 동시에 처리한다 — Iceberg 적재
계산팀 (driver = 팀장, executor = 팀원)
팀원 수는 실행 전에 정해지고, 실행 중에 바뀌지 않는다

Tez

계산
Hive SQL을 실제 작업으로 바꿔 실행한다 — Hive 적재
Hive SQL 주문서를 받는 또 다른 계산팀

HDFS

저장
파일을 조각내 여러 서버에 복사본과 함께 보관한다
여러 창고에 나눠 보관하는 창고 시스템
파일 하나도 조각(block) 단위로 여러 창고에 흩어진다

Hive Metastore

목록
테이블이 어느 파일로 이루어졌는지 목록을 관리한다
도서관 목록 카드
목록 카드가 없으면 파일이 있어도 찾지 못한다. 목록은 Oracle DB에 저장된다

Iceberg

목록
파일 목록과 적재 이력을 메타데이터 파일로 관리한다
새 서류만 덧붙이는 장부
장부도 파일로 저장되고, 쌓이면 정리(유지보수)가 필요하다
