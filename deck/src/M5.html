YARN 자원 배분

  1. 1ResourceManager — 자원 배정 담당

    클러스터 전체의 CPU · 메모리를 보고 작업에 나눠 준다. 비유: 공용 작업장의 자리 배정 담당.

  2. 2 NodeManager · container

    서버마다 NodeManager가 있고, 받은 자원으로 container를 띄운다. 단, 나눠 주는 것은 자리가 아니라 CPU · 메모리 묶음이다.

  3. 3Spark와 Tez가 같은 자원을 나눠 쓴다

    Spark 작업도 Tez 작업도 container 안에서 돈다.

  4. 4 다 차면 queue에서 기다린다

    남은 자원이 없으면 새 작업은 ACCEPTED 상태로 기다린다 — 06 모니터링에서 화면으로 본다.

Spark 작업 구성 — driver와 executor

  1. 1큰 계산을 작은 task로 쪼갠다

    데이터를 조각으로 나눠 여러 서버에서 동시에 계산한다.

  2. 2driver — 팀장

    task를 나눠 맡기고 결과를 모은다. cluster 모드라 driver도 YARN container 안에서 돈다.

  3. 3 executor — 팀원

    각자 맡은 task를 동시에 계산한다. 비유: 계산팀(driver = 팀장, executor = 팀원).

  4. 4팀원 수는 미리 정해진다

    단, 실제 팀과 달리 실행 중에 팀원이 늘거나 줄지 않는다.

Airflow Task와 YARN application

  1. 1Spark Task가 작업을 제출한다

    SparkSubmitOperator가 YARN에 Spark 작업을 제출한다(cluster 모드).

  2. 2application ID가 생긴다

    application_… 번호가 붙고 ACCEPTED가 된다. Airflow log에도 이 번호가 찍힌다 — 06 모니터링.

  3. 3container를 받으면 RUNNING

    driver와 executor가 YARN container에서 계산한다.

  4. 4worker는 끝날 때까지 지켜본다

    끝나면 FinalStatus에 따라 Airflow Task가 성공 · 실패가 된다. 그래서 실행 중인 Spark Task가 있을 때 worker를 재시작하지 않는다 — 07 장애 대응.

YARN application 상태

  1. 1State — 지금 어디쯤인가

    ACCEPTED(자원 대기) → RUNNING(실행 중) → FINISHED(끝남). 실행 중 실패하거나 중지되면 FAILED · KILLED가 되기도 한다.

  2. 2FinalStatus — 끝난 결과

    SUCCEEDED · FAILED · KILLED. 실행 중에는 아직 정해지지 않았다(UNDEFINED).

  3. 3성공 여부는 FinalStatus로 본다

    "끝남"과 "성공"은 다르다. ACCEPTED에 오래 머물면 자원을 기다리는 중이다 — 06 모니터링.

이름이 같은 다른 개념 — Task · Executor

Airflow

Task
DAG 순서도의 한 칸. Grid 화면의 칸 하나. 예: Spark Task 하나
Executor
Task를 어떻게 실행할지 정하는 방식. as-is는 CeleryExecutor(worker가 대기열에서 꺼내 실행)

Spark

task
Spark 작업을 쪼갠 작은 계산 조각. 작업 하나에 수백 개가 넘을 수 있다
executor
task를 실제로 계산하는 프로세스(팀원). YARN container 안에서 돈다
