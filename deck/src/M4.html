테이블 = 파일 + 목록

  1. 1HDFS — 파일을 보관한다

    파일을 조각(block)으로 나눠 여러 서버에 복사본과 함께 둔다. 비유: 창고 시스템 — 단, 파일 하나도 조각으로 흩어진다.

  2. 2Hive Metastore — 목록을 관리한다

    어느 테이블이 HDFS의 어느 폴더 · 파일인지, 열은 무엇인지 적어 둔 목록 카드.

  3. 3테이블 = 목록 + 파일

    조회하면 목록에서 위치를 찾고 HDFS의 파일을 읽는다. 목록이 없으면 파일이 있어도 찾지 못한다.

  4. 4목록은 Oracle DB에

    Hive Metastore의 목록은 Oracle DB에 저장된다.

Hive 테이블과 파티션

  • …/{테이블}_raw TEXTFILE
    • dt=20261022
    • dt=20261023
    • dt=20261024
      • 그날 데이터 파일 …
  • …/{테이블}_orc ORC
    • dt=20261020
    • dt=20261021
  • …/{테이블}_temp ORC · 파티션 없음
    • ORC 파일 …
  1. 1 테이블 = HDFS 폴더 하나

    Hive 테이블의 데이터는 HDFS 폴더 하나에 파일로 모여 있다.

  2. 2파티션 = 날짜별 하위 폴더

    _raw · _orc는 dt=YYYYMMDD 폴더로 날짜마다 나뉜다(dt는 8자리 날짜 문자열).

  3. 3날짜로 조회하면 그 폴더만 읽는다

    조회할 날짜(dt)를 주면 그 날짜 폴더만 읽어 빠르다.

  4. 4_temp는 파티션이 없다

    하위 폴더 없이 파일만 있다 — 적재 중간에 잠깐 쓰는 테이블이다.

파일 형식 — TEXT와 ORC

TEXT (TEXTFILE) _raw

  • 글자 그대로 한 줄에 한 건씩 저장한다
  • 사람이 읽기 쉽지만, 조회할 때 전부 읽어야 한다

ORC _temp · _orc

  • 열 단위로 모아 압축해 저장한다
  • 조회할 때 필요한 열만 읽어 빠르고 공간도 덜 쓴다

Iceberg 테이블의 Parquet도 ORC처럼 열 단위 형식이다.

Hive 데이터의 두 테이블 — _raw와 _orc

  1. 1_raw — 최근 데이터

    새 데이터가 계속 쌓이는 TEXT 테이블.

  2. 2_orc — 예전 데이터

    배치 주기마다 ORC로 바꿔 옮겨 둔 테이블.

  3. 3 날짜에 따라 테이블을 골라 조회한다

    예전 데이터는 _orc, 최근 데이터는 _raw에서 본다.

  4. 4_raw는 비우지 않는다

    retention 처리 때만 오래된 데이터를 지운다. 옮기는 과정은 다음 장.

Hive 적재 6단계

  1. 1새 데이터를 _raw에 계속 Insert

Iceberg 적재와 snapshot

  1. 1 snapshot — 그 시점의 테이블 모습

    적재가 끝날 때마다 하나씩 생긴다.

  2. 2적재 = 새 파일을 덧붙인다(append)

    기존 파일은 그대로 두고 새 데이터 파일만 추가한다.

  3. 3조회는 현재 snapshot을 읽는다

    마지막으로 끝난 적재까지가 보인다.

  4. 4비유: 테이블 전체 사진

    단, 내용을 복사하지 않고 그 시점의 파일 목록만 기록한다. 그래서 예전 모습도 남는다.

Iceberg 유지보수 — Compaction · snapshot 정리

Compaction — 작은 파일 합치기

  • append를 반복하면 작은 파일이 많이 쌓여 조회가 느려진다
  • 비유: 흩어진 서류를 큰 묶음으로 다시 철하기

오래된 snapshot 정리

  • snapshot이 쌓이면 메타데이터와 지워진 줄 알았던 옛 파일이 남는다
  • 오래된 것을 정리해 공간을 되찾는다
