DAG와 Task

  1. 1 DAG — 작업 순서도

    할 일(Task)을 순서대로 이은 것. 비유: 레시피 — 단, 정해진 주기마다 반복 실행된다.

  2. 2Task — 순서도의 한 칸

    앞 Task가 성공해야 다음 Task가 시작된다(기본 규칙).

  3. 3DAG Run — 한 번 실행한 기록

    주기마다 하나씩 생긴다. Grid 화면에서 열 하나가 DAG Run 하나, 칸 색이 Task 상태다.

  4. 4멈췄다 켜도 몰아서 돌지 않는다

    멈춰 있던 동안 지나간 주기를 한꺼번에 실행하지 않고, 가장 최근 것 하나만 만든다(catchup=False).

처리 범위 — PARAM

  1. 1 PARAM — 처리할 날짜 범위

    DAG가 받는 입력값. 비유: 작업 지시서의 "처리할 기간" 칸.

  2. 2범위 안의 데이터만 처리한다

    DAG는 PARAM에 적힌 날짜 범위에 해당하는 데이터만 골라 처리한다(다음 장의 get_jobs).

  3. 3범위가 정해지는 두 가지 경우

    정해진 주기로 돌 때는 [사용자 작성: 범위가 정해지는 방식]. 다시 돌릴 때는 Trigger DAG 화면에서 PARAM에 날짜 범위를 직접 넣는다 — 07 장애 대응.

처리 대상 고르기 — get_jobs와 job_history

  1. 1get_jobs가 PARAM의 범위를 받는다

    DAG의 첫 단계에서 처리할 날짜 범위를 넘겨받는다.

  2. 2 job_history에서 처리 대상을 고른다

    job_history는 데이터 건마다 처리 상태를 적어 두는 적재 대장. 비유: 택배 배송 조회표 — 단, DAG가 직접 읽고 고쳐 쓴다. [사용자 작성: 고르는 상태 값]

  3. 3Hive SQL · Spark Task가 처리한다

    Hive 변환은 처리할 날짜를, Iceberg 적재는 처리할 파일 경로를 받는다.

  4. 4그래서 다시 실행해도 중복 적재되지 않는다

    처리 결과가 job_history에 남으므로, 같은 범위로 다시 실행해도 이미 적재한 데이터를 또 쌓지 않는다. [사용자 작성: 상태 값과 기록 시점]

DAG Run 날짜와 처리 범위

  1. 1 화면의 날짜 = logical date

    수동으로 Trigger한 DAG Run에는 버튼을 누른 시각이 찍힌다.

  2. 2처리 범위 = PARAM

    실제로 처리한 데이터의 날짜는 PARAM에 넣은 범위다.

  3. 3둘은 다를 수 있다

    화면 날짜만 보고 어느 날짜를 처리했는지 판단하지 않는다. 처리 범위는 get_jobs Task log에서 확인한다 — 07 장애 대응.

Task 상태와 자동 재시도

  1. 1 정상 흐름

    queued → running → success. 화면의 칸 색이 상태다.

  2. 2 자동 재시도

    실패해도 재시도 횟수가 남아 있으면 up_for_retry가 되고, 잠시 뒤 다시 실행된다. 이때는 기다린다.

  3. 3 실패로 끝남

    failed 재시도까지 실패 · upstream_failed 앞 Task가 실패해 시작 못 함 — 앞 Task의 log를 본다 · skipped는 오류가 아니다.

정리

DAG · Task · DAG Run

DAG는 Task의 순서도, DAG Run은 한 번 실행한 기록
앞 Task가 성공해야 다음 Task가 시작된다

PARAM · job_history

PARAM의 날짜 범위로 get_jobs가 job_history에서 처리 대상을 고른다
그래서 다시 실행해도 중복 적재되지 않는다. 처리 범위는 화면 날짜가 아니라 get_jobs log로 본다

기록 · 대기열: PostgreSQL · pgpool · redis · redis-sentinel
실행 쪽은 재시작으로 복구, 기록 · 대기열 쪽은 담당자에게 전달
